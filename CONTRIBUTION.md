# Contributing to Nepal Places API

We welcome contributions to the Nepal Places API project! Thank you for taking the time to contribute.

## How to Contribute

### 1. Fork the Repository
Click the "Fork" button at the top right of the repository page on GitHub to create your copy of the repository.

### 2. Clone the Repository
Clone the repository to your local machine:
```bash
git clone https://github.com/kushal1o1/NepalPlacesAPI.git
cd NepalPlacesAPI
```

### 3. Create a New Branch
Create a new branch for your feature or bug fix:
```bash
git checkout -b feature-branch
```

Use descriptive branch names like:
- `feature/add-new-endpoint`
- `bugfix/fix-pagination-issue`
- `docs/update-readme`

### 4. Make Your Changes
Add new features or fix bugs in the codebase. Ensure your code follows the project's coding standards.
See [STANDARDS](./STANDARDS.md)

### 5. Commit Your Changes
Commit your changes with a descriptive message:
```bash
git commit -m "feat:Add a descriptive message about your changes"
```

### Commit Message Guidelines
- use standards feat,docs,refactor,fix prefix
- Limit the first line to 72 characters or less
- Reference issues and pull requests when relevant

### 6. Push to Your Forked Repository
Push your changes to your forked repository:
```bash
git push origin feature-branch
```

### 7. Open a Pull Request (PR)
1. Go to the original repository on GitHub
2. Click on the "Pull Requests" tab
3. Click the "New Pull Request" button
4. Select your branch and submit the PR with a description of your changes

## Guidelines

### Code Style
- Follow the existing code style in the project
- Use meaningful variable and function names
- Write clear and concise comments where necessary
- Follow PEP 8 guidelines for Python code

### Documentation
- If you add new features, update the documentation accordingly
- Update the API_DOCUMENTATION.md if you add or modify endpoints
- Add docstrings to your functions and classes

### Tests
- Include tests for new features
- Ensure all existing tests pass before submitting a PR


### Code Review Process
- All submissions require review before merging
- Be responsive to feedback and questions
- Make requested changes in a timely manner

## Types of Contributions

### Bug Reports
If you find a bug, please create an issue with:
- A clear and descriptive title
- Steps to reproduce the bug
- Expected behavior vs actual behavior
- Screenshots if applicable
- Your environment details (OS, Python version, Django version)

### Feature Requests
If you have an idea for a new feature:
- Create an issue describing the feature
- Explain why this feature would be useful
- Provide examples of how it would work

### Code Contributions
- Bug fixes
- New features
- Performance improvements
- Documentation improvements

## Issues

If you encounter any issues or have questions about contributing, please feel free to open an issue in the repository.

## Communication

- Be respectful and constructive in all interactions
- Follow the code of conduct
- Ask questions if you're unsure about something

## Getting Help

If you need help with your contribution:
- Check existing issues and pull requests
- Review the documentation
- Open a new issue with your question

## Recognition

Contributors will be acknowledged in the project. Thank you for making Nepal Places API better!
